# 微动星瞳游戏 Demo

这是儿童游戏端的可交互原型，供小组讨论界面、玩法与操作方式。暂不包含家长端和真实硬件连接。

## 运行

安装 Node.js 20 或更新版本后，在项目文件夹运行：

```sh
npm run dev
```

浏览器打开终端显示的 `http://127.0.0.1:4173`。不需要安装第三方依赖。也可直接用浏览器打开 `dist/index.html`。

## 当前内容

- 小鸡首页 → 三阶段入口 → 游戏。
- 四个示例关卡：让小鸡跳舞、让小车开起来、摘下红苹果、点亮小星星。
- 菜单中的关卡预览与拍击、精准点击、接触停留设置。
- 暂停、继续、重玩和完成反馈。

三个阶段的任务区别目前仅用于原型演示，不能视为已经确认的临床训练配置。当前原型在后两个阶段增加了目标数量；正式内容仍需依据原方案和个体需求重新细化。

## 修改哪个文件

| 文件 | 用途 |
| --- | --- |
| `dist/index.html` | 页面入口与基础说明 |
| `dist/style.css` | 黑底配色、大小、布局、横竖屏适配和动画 |
| `dist/game.js` | 物体图形、关卡名称、任务逻辑、输入方式和菜单 |
| `preview.mjs` | 本机预览服务 |
| `TASKS.md` | 团队进度与待办 |
| `CONTRIBUTING.md` | 小组共同修改流程 |

`game.js` 中的 `arts` 是物体素材，`levels` 是关卡文案，`modes` 是交互方式；`S` 保存当前会话状态。当前所有素材均为代码绘制，无需额外图片文件。

## 检查修改

```sh
npm run check
npm test
```

自动检查覆盖核心游戏状态与输入流程。修改布局或触控后，还应在实际手机和平板上试玩；自动检查不能替代实机验证。

## 协作与发布

建议用私有 GitHub 仓库作为代码的统一来源：一个修改建一个分支，经另一位组员检查后合并。具体步骤见 `CONTRIBUTING.md`。

当前已经发布的试玩版本由项目负责人维护。新建 GitHub 仓库后，不会自动更新原来的 Sites 试玩链接；确认合并后，需要同步并发布对应版本。`TASKS.md` 中应记录试玩版对应的提交，防止各自看到不同版本。

此交接包不包含原项目的 Git 历史、托管服务身份、访问凭据或成员名单。GitHub 协作权限与试玩网站访问权限应分别配置。
