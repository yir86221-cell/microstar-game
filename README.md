# 微动星瞳游戏 Demo

这是儿童游戏端的可交互原型，供小组讨论界面、玩法与操作方式。包含全局家长入口及占位页；家长端主体和真实硬件连接尚未实现。

## 小组成员从这里开始

每位成员都可以使用自己的 AI 编程工具提出设计、修改并提交个人分支。开始前接受仓库邀请，并为自己的工具完成仓库读写授权。

- [Word 使用说明与六套提示词](docs/微动星瞳-小组AI协作使用说明.docx)：下载后用 Word 或 WPS 打开。
- [在线阅读同一份说明](docs/微动星瞳-小组AI协作使用说明.txt)：无需下载，可直接复制提示词给自己的 AI。
- [团队任务与进度](TASKS.md)：认领本次负责的页面或关卡。
- [协作流程](CONTRIBUTING.md)：个人分支修改、试玩、提交合并请求，再由小组检查。

GitHub 同步的是已经提交的代码，不会自动同步各人的聊天记录。合并代码也不会自动更新现有试玩网站。

## 运行

安装 Node.js 20 或更新版本后，在项目文件夹运行：

```sh
npm run dev
```

浏览器打开终端显示的 `http://127.0.0.1:4173`。不需要安装第三方依赖。也可直接用浏览器打开 `dist/index.html`。

## 当前内容

完整软件保留 P1「发现目标」、P2「认识物品」、P3「生活探索」三个阶段入口。
P1 共 10 关，前两关黄球、黄星各一次回应后自动进入下一关；第三关红黄蓝小球依次点击，发光保持鲜艳原色。
P1 第 5、8、9、10 关使用三次点击逐段加速，到终点后成功；第 6 关在左侧、右下、左上不同位置再出现。后续关卡分别使用绿色、橙色、粉色与紫色。
P2 已撤销十关重做，恢复为之前的小鸡、小车、苹果、小星星四个示例任务；P3 同样保留原来的四任务/三目标演示逻辑，不擅自改动。

菜单支持选关、拍击/精准点击/接触停留；P1 新增关卡支持声音与降低难度设置。说明见 [当前关卡说明](docs/p1-p2-levels.md)。
所有内容均为软件原型，表现仅供观察，不换算为临床分级或疗效。

## 修改哪个文件

| 文件 | 用途 |
| --- | --- |
| `dist/index.html` | 页面入口与基础说明 |
| `dist/style.css` | 黑底配色、大小、布局、横竖屏适配和动画 |
| `dist/game.js` | 物体图形、关卡名称、任务逻辑、输入方式和菜单 |
| `preview.mjs` | 本机预览服务 |
| `TASKS.md` | 团队进度与待办 |
| `CONTRIBUTING.md` | 小组共同修改流程 |

`game.js` 中的 `arts` 是物体素材，`levels` 是关卡文案，`modes` 是交互方式；`S` 保存当前会话状态。当前所有素材均为代码绘制，无需额外图片文件。

## 检查修改

```sh
npm run check
npm test
```

自动检查覆盖核心游戏状态与输入流程。修改布局或触控后，还应在实际手机和平板上试玩；自动检查不能替代实机验证。

本分支附带 `.github/workflows/check.yml`。该配置合并到仓库并且 GitHub Actions 被允许运行后，会对后续推送与合并请求执行上述两项检查。实际结果以 Actions 页面和合并请求中的检查状态为准。

## 协作与发布

当前按小组决定使用公开 GitHub 仓库作为代码的统一来源。公开可读，编辑权限仍需邀请或通过合并请求协作。一个修改建一个分支，经另一位组员检查后合并。具体步骤见 `CONTRIBUTING.md`。

当前已经发布的试玩版本由项目负责人维护。新建 GitHub 仓库后，不会自动更新原来的 Sites 试玩链接；确认合并后，需要同步并发布对应版本。`TASKS.md` 中应记录试玩版对应的提交，防止各自看到不同版本。

此交接包不包含原项目的 Git 历史、托管服务身份、访问凭据或成员名单。GitHub 协作权限与试玩网站访问权限应分别配置。

所有页面保留右下角家长入口与占位页，进入时暂停，返回恢复原页面。

## 家长入口整合

右下角家长入口已连接 parent-app，打开期间儿童游戏暂停，返回保留关卡和进度。家长端计划与演示数据目前独立，尚未与儿童游戏同步记录；第四阶段仅在家长端。

首次运行先在 parent-app 执行 pnpm install --frozen-lockfile，再在根目录执行 npm run build:parent；随后 npm run dev 可同时预览两端。发布前同样运行 npm run build:parent，将生成的 dist/parent 与儿童端一起部署。家长端源码仍由原组员维护，生成文件不手工修改。
