# 第四阶段蓝牙控灯按钮

本次只新增家长端「训练 → 实物（第四阶段）」计划卡里的一个蓝牙控灯按钮及其必要接入。前三阶段、儿童游戏、原来的设备页和自动实物训练流程不改。

## 使用

1. 电脑在本项目目录运行 `npm run dev`，用 Chrome / Edge 打开终端显示的 localhost 地址，进入家长端，选择「实物」。不能直接双击 HTML 来使用蓝牙。
2. 点击「蓝牙控灯：开始闪烁」，在选择器中选择 MicroStar。安卓 App 首次使用还需要允许蓝牙权限；Android 11 及更旧系统的蓝牙扫描可能要求位置权限。
3. 按钮使用当前计划中的颜色和亮度；默认计划是红色、亮度 75。参数可在原有「调整参数」中修改。
4. 再次点击同一按钮发送停止指令，并断开连接。

手动控灯期间原有自动训练按钮暂不可点击，避免两路同时向同一盏灯写指令。已有训练设备连接时，需要先在设备页断开，才能使用手动控灯。离开此页面、关闭家长端或活动期间切到后台时，会尝试发送停止并断开；设备失联时不能确认灯的实际状态。

沿用已有档案限制：禁用闪烁或关闭震动的档案不会启动此固件的闪烁功能。新文件没有定义常亮或禁用设备拿起震动的指令，所以不会自行发明替代字节。停止按钮不受这些启动限制影响。

## 协议依据

读取了用户放入原文件夹的 `micro_star_client.js` 和 `micro_star_parent.html`，保持它们原样。新按钮仅使用两个文件中明确实现的控灯部分：

- 服务：`8a1f0001-3c4d-4e5f-9a6b-7c8d9e0f1a2b`。
- LIGHT：`8a1f0003-3c4d-4e5f-9a6b-7c8d9e0f1a2b`，原始 5 字节 `[红,绿,蓝,暖白,亮度]`，亮度最多 128，并保留已有较低亮度限制。
- ALERT：`8a1f0002-3c4d-4e5f-9a6b-7c8d9e0f1a2b`，原始单字节 `01` 开始闪烁、`00` 停止。先写 LIGHT，再写 ALERT。
- 不发送串口文本，不使用未在新文件中定义的 `02/03/80` 模式；不订阅运动数据、不写训练成绩。

电脑使用 Web Bluetooth；安卓 0.1.2 使用 Capacitor 原生 BLE，调用在顶层 WebView 处理，再供同源家长 iframe 使用。不会静默切换到模拟灯。

## 验证

`npm run check`、`npm test`、家长端 112 项测试与类型检查通过。新增测试覆盖协议字节、亮度限制、连接取消、写入失败、停止顺序、断开和仅第四阶段显示按钮。

界面按电脑 1200×900、手机 412×915、平板 1024×768 检查；浏览器使用测试蓝牙接口验证按钮启停及数据包，没有伪称连接真实硬件。安卓原生桥接测试、APK 构建、签名和资源一致性检查通过。

没有连接安卓真机或 MicroStar 灯具，因此蓝牙扫描、系统授权及灯具实际响应仍待实机确认。界面「已发送」表示写入调用成功，不代表已由传感器确认灯亮。
