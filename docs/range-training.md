# 新硬件测距训练 · v0.1.10

依据用户提供的 [软件交接](hardware/MicroStar软件交接.md) 和 [原始测试页](hardware/micro_star_train.html)。原件保留，旧 `micro_star_client.js` 的 7 字节 IMU 协议不再用于本版本训练。

## 使用

家长空间 → 训练 → 实物 → 进入实物训练。连接后选择红、绿、蓝、独立暖白或黄，调节亮度（最多 128），点「确认颜色和亮度」。只确认颜色不会开灯，可使用试灯闪烁或试灯恒亮。

把模块放在物品外，朝向物品。页面显示当前厘米数、有效性及稳定性；无有效距离或没有确认颜色时不能开始。稳定是准备提示，不是自动开始条件。家长点「开始找」，等待设备确认；颜色/亮度在寻找及已找到期间锁定。

设备报告已找到时，记录设备返回的毫秒用时；每轮只记录一次。家长点「结束训练」，收到调试状态后才可下一轮。不自动循环、不在手机重新计算拿起阈值、不发送震动或呼吸控制指令。找到后的呼吸和三次震动由设备执行；要求关闭震动的档案暂不能启动实物训练。

离开本页/进入后台会请求关灯并断开。连接断开、测距数据 3 秒未更新，已确认开始的回合记为中断；未确认开始不造成功记录。开始/结束 5 秒未确认会断开并提示，不自动重发开始指令。蓝牙写入完成不等于实灯已按预期动作，停止未确认时检查硬件。

## 协议和记录

- UUID 沿用，颜色仍为 RGB + 独立暖白 + 亮度 5 字节。
- 指令仅允许 `00`、`01`、`02`、`10`、`11`（十六进制）。
- 两端订阅测距特征；10 字节小端解析阶段、有效/稳定标志、当前/初始距离和设备用时。7 字节旧通知明确拒绝。
- 总状态第一字节支持关/闪/恒亮/呼吸，第三字节解释为距离有效，不再显示 IMU 正常。
- 只有本页发起并经设备确认的回合才保存。重连读到的旧「已找到」不会补记。重复通知、结束中的晚到通知不能重复计数。
- 记录附原始数值、颜色亮度及 `range` 判定来源；设备测距记录与触屏命中率分开展示，CSV 附设备用时和距离，不转换为抓握能力或康复分数。旧记录保留。

## 电脑和安卓交付

源码在 `codex/v0.1.10-range-training`，同一套家长端界面用于两端。安卓使用原生 BLE，电脑 Chrome/Edge 使用 Web Bluetooth（localhost 或 HTTPS）。不能用不支持蓝牙的浏览器假装连接成功。

电脑构建包 `microstar-web-v0.1.10.zip` 含完整网页与本机抠图模型。解压后在该目录执行 `python -m http.server 4173 --bind 127.0.0.1`，用电脑 Chrome/Edge 打开 `http://localhost:4173`。不必安装 Node；不要双击 HTML 进行蓝牙测试。

安卓 `microstar-android-v0.1.10.apk` 为同签名侧载测试包，覆盖安装，勿先卸载。硬件必须刷入交接文档对应的测距固件；本仓库没有固件烧录文件，也没有自动更新硬件的能力。
