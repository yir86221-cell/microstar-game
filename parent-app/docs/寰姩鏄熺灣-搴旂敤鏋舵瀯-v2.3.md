# 微动星瞳 · iPad 应用架构（v2.3）

> **本版变更**（v2.2 → v2.3）
>
> 1. **去掉「今日」Tab**，4 个 Tab：训练 / 数据 / 设备 / 我的。
> 2. **开屏直接进训练页**——家长打开 App 的唯一高频动机就是"今天练什么"。
> 3. **数据 Tab 简化**：状态条 + 小趋势图 + 三个指标 + 最多 2 条建议 + 入口列表；
>    计划编辑从内联表单**移成二级页**。
> 4. **设备页在 1–3 阶就显示「未连接」**，不做引导文案。
>
> **v2.2 已定、本版沿用**：只有第 4 阶用灯；1–3 阶纯屏幕、不碰 BLE；连接由家长主动发起、
> 当天实物训练结束即断开；判分只由设备（触屏 / 加速度计）；无「看到了」按钮；
> 右上角长按退出；默认进家长模式；第 4 阶自动回路（亮 30 s / 间隔 8 s / 10 轮）。

---

## 0. 这次改动的实质

v2.1 里我默认"App 打开就连着灯"，于是要操心待机 8 小时、切后台断不断、回前台重连……一整套问题。

但事实上：**灯只在第 4 阶用。而大部分家庭在头几个月都待在第 1–3 阶。**

所以正确的模型不是"App 保持连接"，而是"**第 4 阶的一次训练，借用一次连接**"：

```
第 4 阶开始训练 → 家长点「连接提示灯并开始」 → 连接 → 自检 → 训练
第 4 阶今天练完 → 家长点「今天到此为止」 → 断开
```

这样一改：

| 之前的顾虑 | 现在 |
|---|---|
| 待机 8 小时，一晚就没电 | 只有练实物那几分钟连着，平时是断的 |
| 切后台断不断、回前台重连 | 不练就断，没有"后台还连着"这个状态 |
| 打开 App 等重连 1–2 秒 | 打开 App 不需要灯，零等待 |
| 家长以为灯坏了（其实没电） | 连接是家长主动发起的一次动作，他清楚灯应该在什么状态 |

**连接从一个"环境状态"变成了一个"明确的动作"。** 这是这一版最大的简化。

### 1.2 简化

1. **1–3 阶没有 BLE**。孩子模式是纯屏幕训练，不依赖任何外部设备，也不受灯的电力影响。
2. **连接是一次明确动作**，家长知道灯什么时候该是通的。
3. **判分零延迟**（第 4 阶 `MOTION` 直接进本地 `TrialRunner`）。
4. **判定源唯一**，没有"这一下是谁点的"。
5. **指标只算一次**。

### 1.3 代价

1. 所有人共用一台 iPad。
2. **第 4 阶时 iPad 和灯都要准备好**，缺一个开不了训——比纯屏幕训练多一步。
3. 一台设备坏了就全停。
4. 训练中不能接电话、不能切 App。CVI 孩子一次训练只有十几分钟，打断一次基本要重来。

## 2. 硬约束

### 2.1 约束表

| # | 约束 | 来源 | 对架构的影响 |
|---|---|---|---|
| C1 | BLE 只有 3 个通道：`ALERT`(1 字节)、`LIGHT`(5 字节)、`MOTION`(7 字节 notify) | 蓝牙文档 | 封装成协议层，字节不散落在 UI |
| C2 | 没有电量 / 充电 / 固件版本 / 按键事件上报，短期不加 | Q4 | 电量功能全砍，用「自检 + 用量积分」替代（2.5） |
| C3 | 亮度固件上限 128/255；满亮 0.4–0.6 A；电池 400 mAh | 硬件文档 | 连续满亮只有 43 分钟（2.4） |
| C4 | 充电时设备停止运行，无电源路径管理 | 硬件文档 | 「充电中」与「没电」在 App 看来一样，靠引导区分 |
| C5 | 闪烁固定 200 ms 亮灭（2.5 Hz） | 蓝牙文档 | 逼近光敏阈值，不得提供更快闪烁 |
| C6 | `MOTION` 只在状态**变化**时推送，只可靠给出 moving 0/1 | 蓝牙文档 | 回合必须**等放下**（4.3） |
| C7 | CVI 儿童视觉延迟 5–20 s+ | 产品文档 | 判定窗口与回路亮起时长都必须 **≥30 s** |
| C8 | **只有 iPad 一台设备** | 本轮 | 删掉跨端通信；iPadOS 不支持 Web Bluetooth，仍需 Capacitor 原生壳 |
| C9 | 有**马达**（可穿戴型），无音频，App 控不了震动 | Q6 | 固件绑 `ALERT` 边沿自触发（2.6） |
| C10 | iPad 支持系统级**引导式访问** | iOS 能力 | 孩子模式的可选加强防线（3.4） |
| C11 | **触摸事件不携带身份** | 本轮 | 判定源必须唯一；退出区必须从判分区扣除（2.2） |
| **C12** | **1–3 阶不需要灯；连接只服务第 4 阶** | 本轮 | 连接生命周期 = 实物训练周期（3.3） |

### 2.2 判分：每个阶段只有一个判定源

| 阶段 | 判定源 | 信号 | 灯 |
|---|---|---|---|
| **1–3 阶** | **触屏** | 任意触碰 / 接触悬停 1.2 s / 精准触碰 | **不用** |
| **4 阶** | **加速度计** | `MOTION` moving 0 → 1 | 用（回路控制） |

没有家长手动标记。

为什么能这么干净：全屏拍击本身就是为重度患儿设计的——手掌、拳头、手背任何部位触碰都算命中，目的正是建立"动作 → 反馈"的因果。孩子必须碰，这本来就是设计的一部分。

而只要存在手动标记，就必然出现"这一下是谁点的"。单设备上无解（触摸事件不带身份），唯一干净的解法是不让它存在。

#### 退出区必须从判分区里扣掉

孩子模式右上角有一块区域给家长退出。如果它也计入判分，**家长每按一次退出就会顺带记一次命中**——数据被系统性污染，而且看不出来。

1. 退出区在屏幕**右上角**，最小 48×48 pt。
2. 这块区域内的一切触摸**不判命中**，直接交给退出逻辑。
3. 退出需要**长按 1.2 秒**——脑瘫儿童的不自主运动扫过角落是常事。

### 2.3 反馈通道

| 通道 | 谁控制 | 架构处理 |
|---|---|---|
| **视觉（RGBWW 灯）** | App | 第 4 阶的主反馈；1–3 阶没有灯 |
| **触觉（马达）** | 只有固件 | 绑 `ALERT` 边沿触发（2.6） |
| **听觉（iPad 扬声器）** | App | **默认关闭** |

> CVI 孩子听觉往往比视觉好。若每次命中都有声音，孩子会学会"靠听定位"，视觉通路被绕过。
> 但 1–3 阶没有灯，奖励只能靠屏幕本身（目标放大/变色）。这也是声音最容易被误用的地方——更要守住。

### 2.4 续航（本版重算）

前提：电池 400 mAh @3.7 V 按 90% 可用（360 mAh）；升压效率 85%；ESP32-C3 BLE 常连 30 mA @3.3 V；SK6812 RGBWW 7 灯满白 ≈ 0.56 A @5 V；马达短震摊薄忽略。

**连续点亮时**（理论最坏情况）：

| 亮度 | 电池侧电流 | 连续点亮续航 |
|---|---|---|
| 128/255（固件上限） | ≈ 500 mA | ≈ 43 分钟 |
| 75/255（推荐） | ≈ 320 mA | ≈ 67 分钟 |
| 50/255 | ≈ 230 mA | ≈ 93 分钟 |
| 灯灭，仅 BLE 连接 | ≈ 45 mA | ≈ 8 小时 |

**但第 4 阶不是连续点亮的**，回路是"亮 X 秒 / 灭 Y 秒"循环。按默认参数算：

| 项 | 数值 |
|---|---|
| 每轮：亮 30 s + 间隔 8 s | 38 s |
| 10 轮 | 6.3 分钟 |
| 灯亮总时长 | 5 分钟 |
| 灯亮消耗 | 5 min × 320 mA ÷ 60 ≈ **26.7 mAh** |
| 连接待机（间隔 + 收尾） | ≈ 4 mAh |
| **单次第 4 阶训练合计** | ≈ **31 mAh ≈ 8.6%** |
| **满电可练** | **约 10–12 次** |

**结论**：

1. **1–3 阶完全不耗灯的电**——灯可以几个月不充电（仅自放电）。
2. **第 4 阶一次训练约 8–9% 电**，满电约 10–12 次；这比 v2.1 里"3–5 次"乐观得多，因为那时我按连续点亮 15 分钟算的，而实际是间歇点亮。
3. 攒够 3–4 次第 4 阶训练再充电就行——但**因为读不到电量，仍建议"每次实物训练结束后顺手插上"**，比算着用可靠。
4. 亮度越高、轮数越多，线性变差。

> 精度 ±30%，用 USB 电流表测三个点位替换。这张表走云端配置下发（M13）。

### 2.5 设备健康（只在第 4 阶出现）

因为只有第 4 阶用灯，设备健康相关的三个动作都收进"开始实物训练"这个动作里：

1. **训练前自检**：点「连接提示灯并开始」→ 连上 → 立即试亮一次 → 亮起来就是"可用 ✓"。灯亮 = 有电，这是唯一诚实的判断。
2. **用量积分**：只统计第 4 阶的亮灯分钟 × 亮度，折算"自上次充电以来还能练几次"。家长每次充好电点「已充满」归零。
3. **没电排查**：连不上时给有序清单，第一条永远是"先插上充电 10 分钟再试"。

**不做电量显示**——错的数字比没有数字更糟。

**尴尬的事实**：充电时设备停机，"充满"和"没电"在 App 眼里一样。引导里要反复讲：**充 1.5 小时后拔线再连**。

### 2.6 马达：不开通道，固件在边沿自震

`ALERT=1` → 亮灯 + 轻震；`ALERT=0` → 熄灯 + 轻震。五个用法：回合边界、放下确认、寻灯、触觉引导节奏、抓握反馈。

三条注意：**震动污染加速度计**（固件屏蔽 300 ms）；**触觉防御**（档案标记可关）；**耗电**。

## 3. 总体架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────────────┐
│ L5 表现层                                                         │
│   孩子模式：全屏训练场（1–3 阶，不用灯，只留右上角退出区）          │
│   家长模式：今日 / 训练 / 数据 / 设备 / 我的                        │
│   实物训练台：家长模式里的全屏页（4 阶，自动回路 + 用灯）            │
├──────────────────────────────────────────────────────────────────┤
│ L4 用例层  建档 · 发布计划 · 开始训练 · 结束结算 · 生成周报 · 提纯    │
├──────────────────────────────────────────────────────────────────┤
│ L3 领域层（纯逻辑，可单测）                                        │
│   档案域 · 计划域 · 素材域 · 会话域 · 指标域 · 用量积分 · 报告域      │
├──────────────────────────────────────────────────────────────────┤
│ L2 能力层  BLE 网关(native) · 连接生命周期 · 自动回路 · 素材提纯      │
├──────────────────────────────────────────────────────────────────┤
│ L1 数据层  本地库（离线优先）· 云库 · 事件日志（不可变，可重算）       │
├──────────────────────────────────────────────────────────────────┤
│ L0 设备层  ESP32-C3（ALERT / LIGHT / MOTION，不扩通道）              │
└──────────────────────────────────────────────────────────────────┘
  横切：账号与家庭 · 隐私合规 · 埋点与灰度 · 错误上报
```

**一条原则**：指标只能由 L3 的纯函数从**原始事件**算出来，不能由 UI 顺手累加。

### 3.2 代码结构

```
packages/
  core-protocol/   BLE 编解码、UUID、命令队列、重连状态机
  core-domain/     实体、指标、回合编排、自动回路、用量积分（无 IO 纯函数）
  core-data/       本地库 schema、同步协议、迁移
  ui-kit/          设计系统（孩子模式大色块 / 家长模式高信息密度）
apps/
  app/             唯一 App（Capacitor 壳）
    src/modes/
      child/       孩子模式：全屏训练场（不依赖 BLE）
      parent/      家长模式：五个 Tab + 实物训练台（依赖 BLE）
    src/services/  设备服务（连接生命周期）、会话仓库
native/
  ble-bridge/      iOS 原生 BLE 插件（CoreBluetooth）
services/
  api/             同步、素材、报告、配置下发
```

### 3.3 连接生命周期（D13 已定）

**一句话：连接跟着"一次实物训练"走，不跟着 App 走。**

```
App 启动
   └─ 不连接。设备状态未知，也不需要知道
   └─ （若之前已配对过，只记住设备，不自动连）

家长准备练第 4 阶
   └─ 训练页的第 4 阶计划卡 → 按钮「连接提示灯并开始」
         ├ 已配对且能连 → 连接 → 试亮自检 → 进入实物训练台
         └ 连不上 → 停在排查页，不给开始

实物训练进行中
   └─ 保持连接

一次训练结束（结算页）
   ├ 家长点「再练一次」→ 保持连接，直接下一轮
   └ 家长点「今天到此为止」→ **断开连接** + 提示"顺手插上充电"

兜底：App 切后台超过 15 分钟且不在训练中 → 自动断开
     （第 4 阶训练是连续的，不可能挂那么久；防家长忘了点）
```

**必须做对的三件事**：

1. **不要"打开 App 就自动连"**。1–3 阶用户根本没有灯的事，自动连只会制造"设备未连接"的焦虑。
2. **连接失败不能进入训练**。没灯就没有第 4 阶，硬进会得到一屋子 `noResponse`。
3. **断开必须是显式结果**，不是超时副作用。日志要能区分"家长主动断开"和"意外掉线"。

### 3.4 模式切换与闸门（D11 / D12 已定）

| 规则 | 结论 |
|---|---|
| **启动默认进入** | **家长模式，落在训练页**（4.1） |
| **进入孩子模式的唯一入口** | 家长模式点「开始训练」，且当前 1–3 阶 |
| **退出孩子模式** | 右上角 48 pt 区域，**长按 1.2 秒** |
| **加强防线（可选）** | 系统引导式访问，首次使用引导里教一遍 |

```
┌──────────────────────────────────────┐
│                        ┌────┐        │
│                        │ 退出│  ← 48pt，长按 1.2s
│                        └────┘        │
│                                      │
│            一个目标                   │  ← 纯黑底、单色、无文字
│                                      │
│     （其余全部区域 = 孩子触碰区）      │
│                                      │
│  回合 3/12                           │
└──────────────────────────────────────┘
```

**不做 PIN。** 摩擦会让家长在整个训练周期里反复被卡，最后干脆关掉。

## 4. 页面地图

### 4.1 家长模式（4 个 Tab，开屏即训练）

| Tab | 主要页面 | 一句话 |
|---|---|---|
| **训练** | 今日状态条 / 四阶轨道 / 本阶素材 / 今日计划 → 开始训练 | **执行**：打开 App 就是这一屏 |
| **数据** | 最近状态 / 趋势 / 三个指标 / 建议 / 入口列表 | **决策**：练得怎样 |
| **设备** | 连接状态 / 连接 / 灯光 / 找灯 / 排查 | **第 4 阶才有意义** |
| **我的** | 孩子档案 / 安全标记 / 交互方式 / 隐私 / 关于 | |

**去掉「今日」Tab，开屏直接进训练页。** 理由：家长打开 App 的唯一高频动机就是"今天练什么"，
再点一次才进训练页是多余的。原来的"今天练了没 / 上次成绩"压缩成训练页顶部的一条状态条。

**设备 Tab 在 1–3 阶就显示「未连接」。** 不做"预备卡"那种引导文案——灯第 4 阶才用，
现在没连是正常状态，不该用一段话去解释它。

划分原则：**按「执行 / 决策」切**——训练页选完就开练，参数编辑从数据页进二级页。

#### 数据 Tab 的简化

v2.2 的数据页塞了趋势图、四个指标、建议、内联计划编辑表单、导出/清空，一屏放不下。改为：

| 区块 | 内容 |
|---|---|
| 状态条 | 今天练了没、上次命中率、P50 |
| 趋势 | 一张小图（最近 8 次），不放图例、不放坐标轴 |
| 指标 | **三个**：命中率、P50 反应、有效训练次数 |
| 建议 | 最多 2 条 |
| 入口列表 | 调整计划 → 二级页 / 导出报告 / 全部数据 |

**计划编辑从内联表单改成二级页**（5 个下拉 + 1 个滑杆占掉半屏，是这一页最重的东西）。
入口就是一行「调整计划 · 判定窗口 30 秒 · 单次 15 分钟」。

### 4.2 孩子模式（1–3 阶，全屏）

- **无 Tab、无导航、无返回手势区**。唯一出口是右上角 48 pt 长按 1.2 秒。
- **纯黑底**，单目标，无背景纹理（视觉拥挤是 CVI 的核心特征）。
- **目标位置**由档案的视野偏好决定。
- **除退出区外，全屏都是孩子触碰区**。
- **不需要灯**，也不显示任何设备状态。
- 进度指示可以关掉。不做分数、星星、排行榜。

### 4.3 两种训练界面，两个不同的入口

| 阶段 | 入口 | iPad 在谁手里 | 判定 | 灯 | 家长要做什么 |
|---|---|---|---|---|---|
| **1–3 阶** | 训练页「开始训练」→ 孩子模式 | 孩子 / 支架 | 触屏 | 不用 | 点一次 |
| **4 阶** | 训练页「**连接提示灯并开始**」→ 实物训练台 | 家长（可放下） | `MOTION` | 用 | 点一次（含连接与自检） |

#### 第 4 阶是自动回路

```
[连接 + 自检]
  → 回路开始，重复 N 轮：
       [门控] 设备是否还拿着？
           ├ 已放下 → ALERT=1 亮起（t0）
           │          → 保持 X 秒（期间若 moving 0→1，记命中 t1）
           │          → ALERT=0 熄灭
           │          → 间隔 Y 秒
           └ 仍拿着 → 灯保持熄灭，等放下
                      → 超过 Z 秒 → 本轮 abort（未放下）→ 下一轮
  → 结束 → 结算页「再练一次 / 今天到此为止」
```

**家长全程不需要点任何东西。**

#### 回路参数（默认值已按 CVI 视觉延迟修正）

| 参数 | 默认 | 说明 |
|---|---|---|
| 亮起时长 X | **30 秒** | **不能短**——CVI 视觉延迟 5–20 秒，亮 8 秒孩子还没反应过来灯就灭了 |
| 熄灭间隔 Y | 8 秒 | 让"熄灭"成为可辨识的信号，也留出放下的时间 |
| 轮数 N | 10 | 10 × 38 s ≈ 6.3 分钟 |
| 未放下等待 Z | 20 秒 | 超时记 abort |
| 颜色 / 亮度 / 模式 | 红 / 75 / 常亮 | 受安全策略约束 |

**命中不改变灯光**：`moving 0→1` 只记录时间戳，灯照常亮满 X 秒再灭。
理由：保持每次刺激的时长一致，数据才可比。奖励放在熄灭时的马达轻震。

#### 自动回路里的门控（关键）

| 状态 | 处理 |
|---|---|
| 已放下（moving=0） | 正常开始下一轮 |
| **仍拿着（moving=1）** | **延后**：灯保持熄灭，等放下；超时记 `abort` |

**为什么不能硬开**：`MOTION` 只在状态变化时推送。灯还拿在手上就亮下一轮，孩子下一次拿起不会触发任何事件——那一轮数据作废，而且看不出来。

这个延后本身也是好信号：灯灭着等他放下，孩子会学到"放下才能继续"。

### 4.4 设备状态卡：三段合一

```
┌──────────────────────────────────┐
│  ● 提示灯 · 连接正常              │  ← 进页面自动跑 3 秒自检
│    刚试亮过，亮度 75              │
│                                  │
│    自上次充电已亮灯 20 分钟        │  ← 一行用量
│    大约还能练 10 次               │
│                                  │
│    ▸ 连不上怎么办？               │  ← 默认折叠；异常时展开
└──────────────────────────────────┘
```

三条规则：**自检是动作不是菜单项**；**用量说"次数"不说"分钟"**；**排查清单默认收起**。

## 7. 关键流程

### 7.1 首次使用（5 分钟）

```
建档（8 个字段，可全选"暂不填"）
  → 推荐模板（按 Phase 给 3 套）
  → 试练 3 个回合（纯屏幕，不需要灯）
  → 建议开启引导式访问
  → 回到训练页（开屏所在的那一屏）
```

> **和 v2.1 的区别：首次使用不碰灯。** 灯留到第 4 阶前再配。
> 这样第一次上手是 3 分钟而不是 5 分钟，门槛更低。

### 7.2 屏幕训练（1–3 阶，不用灯）

```
家长模式「开始训练」（唯一动作）
  → 切到孩子模式
  → 全屏、纯黑底、隐藏状态栏
  → 回合循环：
       目标出现（t0）
       → 孩子触碰 → 命中（t1，latency = t1 - t0）
       → 或到判定窗口仍未触碰 → 无反应
       → 屏幕清空 → 间隔 → 下一回合
  → 右上角长按退出 → 结算 → 回家长模式「数据」
```

### 7.3 实物训练（4 阶，含连接与断开）

```
训练页选到第 4 阶 → 计划卡按钮「连接提示灯并开始」
  → 连接（未配对则先配对）
      ├ 失败 → 停在排查页：先充电 10 分钟 / 确认没在充电 / 靠近 / 重启
      └ 成功 → 试亮自检
                └ 不亮 → 同样走排查
  → 进入实物训练台，家长可以把 iPad 放下
  → 回路开始（每轮先过门控）
  → 结束 → 结算页
        ├「再练一次」→ 保持连接，回到回路开始
        └「今天到此为止」→ 断开连接 + 提示"顺手插上充电"
```

### 7.4 周报

```
拉最近 7 天 Session/Trial
  → 按 algoVersion 重算指标（口径统一）
  → 与上一周期对比
  → 规则引擎产出观察（不含结论）
  → 模板渲染 PDF → 导出 / 打印
```

- **回合（Trial）**：一次"呈现目标 → 孩子反应 → 判定"的最小单元。
- **有效回合**：排除断连、跳过、离场、未放下 abort 后的回合，命中率的分母。
- **门控（Gating）**：下一回合的启动条件，本项目主要是"设备已放下"。
- **自动回路（Loop）**：第 4 阶的亮/灭循环程序，家长点开始后自动运行。
- **泛化（Generalization）**：把屏幕上学到的辨别能力迁移到真实物品。
- **判定源（judge）**：`touch`（1–3 阶）或 `motion`（4 阶）。
- **用量积分（UsageLedger）**：用"亮灯分钟 × 亮度"折算消耗，替代不存在的电量传感器。
- **连接租期**：一次实物训练从连接到断开的时间段。
- **孩子模式**：全屏、无导航、不用灯的训练界面，1–3 阶使用。
- **实物训练台**：4 阶的全屏页，含连接、回路、结算三段的完整流程。

## 附录 B · BLE 协议字节表（v1.0 · 可直接交固件）

### B1 服务与特征：**UUID 保持现有，不新增通道**

| 名称 | UUID | 方向 | 长度 |
|---|---|---|---|
| SERVICE | `8a1f0001-3c4d-4e5f-9a6b-7c8d9e0f1a2b` | — | — |
| ALERT | `8a1f0002-3c4d-4e5f-9a6b-7c8d9e0f1a2b` | App → 灯 | 1 字节 |
| LIGHT | `8a1f0003-3c4d-4e5f-9a6b-7c8d9e0f1a2b` | App → 灯 | 5 字节 |
| MOTION | `8a1f0004-3c4d-4e5f-9a6b-7c8d9e0f1a2b` | 灯 → App | 7 字节（notify） |

### B2 `ALERT`（1 字节）：灯的运行模式

| 字节值 | 语义 | 说明 |
|---|---|---|
| `0x00` | 熄灭 | 立即灭灯，保留当前颜色 |
| `0x01` | 闪烁 | 200 ms 亮 / 200 ms 灭（2.5 Hz）。**保持现有行为不变** |
| `0x02` | **常亮** | **新增**。第 4 阶回路呈现目标用它 |
| `0x03` | **呼吸** | **新增**。亮 → 暗 → 亮，周期 2.5–3 s，最暗 ≥20% |

`0x01` 语义不能动，新增值往后排，旧固件收到 `0x02`/`0x03` 直接忽略，天然向后兼容。

### B3 第 8 位：震动抑制标志

| 写法 | 含义 |
|---|---|
| `0x82` | 常亮，且不震动 |
| `0x83` | 呼吸，且不震动 |
| `0x80` | 熄灭，且不震动 |

固件只要两句：`bool mute = (b & 0x80) != 0; mode = b & 0x7F;`

### B4 `LIGHT`（5 字节）

```
[0] 红   [1] 绿   [2] 蓝   [3] 暖白   [4] 亮度
```

亮度 0–255，固件按 **128 截断**；App 默认写 **75**；改颜色不影响当前运行模式。

### B5 `MOTION`（7 字节，notify）

```
[0]      moving：1 = 正在移动/被拿起，0 = 已放下
[1..2]   X  int16 小端，单位 mg
[3..4]   Y
[5..6]   Z
```

只在状态**变化**时推送。

### B6 固件必须配合的三件事

1. **震动屏蔽窗**：`ALERT` 边沿触发马达后，屏蔽加速度判定约 **300 ms**。否则马达自身的震动会被判成"拿起"。
2. **呼吸参数由固件定死**（2.5–3 s / ≥20%），App 不下发。
3. **断开后的功耗**：现在大部分时间灯是断开的，固件必须在无连接后进入低功耗（建议 3 分钟后深睡广播）。否则电池会在一周内被待机吃光。

### B7 本版明确不做的

不加电量 / 充电 / 固件版本特征；不加马达特征；不做 OTA；不改 UUID 与 `LIGHT` 布局。

### B8 固件侧还需确认

`ALERT` 从 `0x02`（常亮）切到 `0x00`（熄灭）时，**回合计时不应被重置**，只是灯灭。
